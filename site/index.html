Pause, point, write. Your agent picks it up, fixes it, and resolves it.

Start with one command

$ npx telestrator path/to/video.mp4

A project folder works too: it opens the newest render. The review opens in your browser, and notes stay on your machine.

$ npx telestrator init

Once, to connect your agent: Claude Code, Codex, Cursor, VS Code, Gemini CLI, Windsurf and more. Then ask it to “check the video feedback”.

How it works

  1. Pause on the frame. Step frame by frame with the arrow keys.
  2. Point at something (P), draw on it (D), or drag the filmstrip for a range.
  3. Write one line. The note lands at the playhead.
  4. Your agent fixes the source, re-renders, checks the frame, and resolves the note. If it's unsure, it asks you under the note.

For agents

An MCP server your agent talks to. It reads and writes the same notes you see, so replies show up in your review as they happen.

get_feedbackOpen notes, with each note's frame as an image
watch_feedbackWaits for your notes while you review: hands-free
get_frameAny frame, to check a fix after a re-render
acknowledge“Seen it, working on it”
replyAsks you a question under the note
resolve · dismissCloses the note, saying what changed or why not
add_noteThe agent critiques the render and leaves its own notes

Works with what you render

HyperFramesPointing names the exact element on that frame, with its source line and styles
RemotionPoints at the spot in the frame; scenes and captions from a sidecar file
Any MP4, MOV, WebMThe spot, the time, the frame, and captions from a .srt or .vtt

Questions

Is it free?
Yes. It's MIT licensed.
Does my video leave my machine?
No. telestrator runs on your machine and uploads nothing: your video stays where it is, and notes are JSON files next to it in .telestrator/. One thing to know: when your agent reads the feedback, the notes and the frames it looks at go to its AI provider (Anthropic, OpenAI…), like any file your agent reads. Commit .telestrator/ if you want the feedback in git.
Which agents work?
Any agent that supports MCP. init sets up the ones you have. Without MCP, use “Copy for agent” and paste.
Do I need HyperFrames?
No. Any video works. With a HyperFrames composition, pointing also knows which element you mean and where it's written.
Something isn't working?
Run npx telestrator doctor. It checks Node, ffmpeg, your agents, and what your video resolves to.
Where's the code?
On GitHub. Issues and pull requests are welcome.
Set up telestrator so I can review my rendered videos and you can act on my feedback.

1. Connect yourself to the telestrator MCP server. Run `npx telestrator init`, or add an MCP server named "telestrator" with command `npx` and args `["-y", "telestrator", "mcp"]`. If I need to restart this session to load the tools, tell me.
2. Find my latest render (check ./renders, ./out and the project folder; ask me if there are several) and open the review for me: `npx telestrator <video or project folder>`. For a HyperFrames project, make sure the composition is found; if it isn't, pass `--composition <path to index.html>`.
3. Run `npx telestrator doctor` and fix anything it flags.

Then, whenever I say "check the video feedback":
- Call get_feedback and read every open note, including its frame image.
- acknowledge each note as you pick it up.
- Fix the source. Each note gives the time and frame, the scene and its file, what's being said, and for pointed elements the source file:line and current styles.
- Re-render, check your fix with get_frame at the note's time, then resolve the note with one line on what you changed.
- If a note is unclear, reply with a question instead of guessing. If you won't change something, dismiss it with the reason.

If I say "watch mode", call watch_feedback in a loop and handle my notes as they arrive.
If I ask you to critique the render, step through it with get_frame and leave your own notes with add_note.
